# 用户故事

遵循 3C 原则（Card、Conversation、Confirmation）与 INVEST 标准创建用户故事。生成的故事包含描述、设计链接与验收标准。

**适用场景：** 编写用户故事、把功能拆解为故事、创建待办项，或定义验收标准。

**参数：**
- `$PRODUCT`：产品或系统名称
- `$FEATURE`：要拆解为故事的新功能
- `$DESIGN`：设计文件链接（Figma、Miro 等）
- `$ASSUMPTIONS`：关键假设或上下文

## 分步流程

1. **分析功能**，基于提供的设计与上下文
2. **识别用户角色**与不同的用户旅程
3. **应用 3C 框架：**
   - Card（卡片）：简单标题与一句话说明
   - Conversation（对话）：对意图的详细讨论
   - Confirmation（确认）：清晰的验收标准
4. **遵循 INVEST 标准：** Independent（独立）、Negotiable（可协商）、Valuable（有价值）、Estimable（可估算）、Small（小）、Testable（可测试）
5. **使用平实语言**，让小学水平的人也能看懂
6. **关联设计文件**作为视觉参考
7. **按结构化格式输出用户故事**

## 故事模板

**标题：** [功能名称]

**描述：** 作为 [用户角色]，我想要 [操作]，以便 [收益]。

**设计：** [设计文件链接]

**验收标准：**
1. [清晰、可测试的标准]
2. [可观察的行为]
3. [系统正确校验]
4. [边界情况处理]
5. [性能或无障碍方面的考量]
6. [集成点]

## 用户故事示例

**标题：** 最近浏览区块

**描述：** 作为线上购物者，我想在产品页看到「最近浏览」区块，以便轻松回看自己曾考虑过的商品。

**设计：** [Figma 链接]

**验收标准：**
1. 对每一位此前浏览过至少 1 个商品的用户，产品页底部都会展示「最近浏览」区块。
2. 对于本次会话中首次访问产品页的用户，不展示该区块。
3. 当前商品本身会从展示的条目中排除。
4. 该区块以商品卡片或缩略图形式展示图片、标题与价格。
5. 每张商品卡片标明浏览时间（例如「5 分钟前浏览」）。
6. 点击商品卡片会把用户带到对应的商品页。

## 输出交付物

- 该功能完整的一组用户故事
- 每个故事包含标题、描述、设计链接与 4-6 条验收标准
- 故事彼此独立，可按任意顺序开发
- 故事的大小适合一个冲刺周期
- 故事引用相关的设计文档
