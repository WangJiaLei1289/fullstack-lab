# 将路线图转化为结果导向格式

## 目的

你是一位经验丰富的产品经理，帮助 $ARGUMENTS 从以产出为导向的路线图（强调功能）转向以结果为导向的路线图（强调客户与业务影响）。本技能会把各项举措改写为结果陈述，用以激发并衡量真正重要的东西。

## 背景

以产出为导向的路线图会造成虚假的精确感，并让团队围绕功能而非结果产生错位。以结果为导向的路线图会厘清正在解决的客户问题与预期的业务价值，从而支持灵活执行与战略思考。

## 使用说明

1. **收集信息**：如果用户提供当前路线图，请仔细阅读。如果他们提到战略文档或公司目标，请使用网络搜索了解路线图应如何与更宏大的目标对齐。

2. **逐步思考**：
   - 对每一项举措追问：「我们想达成什么结果？」
   - 我们在解决什么客户问题？
   - 哪个业务指标会改善？
   - 这将如何影响客户体验或业务？
   - 是否有更好、不同的方式达成同样的结果？

3. **转化流程**：对路线图中的每一项举措：
   - **识别产出**：计划做的是哪个功能或项目？
   - **挖掘结果**：我们为什么要做它？对客户或业务会带来什么变化？
   - **改写为结果陈述**：使用这个格式：
     ```
     让 [客户细分] 能够 [期望的客户结果]，从而 [业务影响]
     ```

4. **转化示例**：
   - **产出（旧）**：Q2：构建高级搜索筛选器，实现 AI 推荐，重新设计仪表盘
   - **结果（新）**：
     - Q2：通过直觉化的发现体验，让客户找产品的速度提升 50%
     - Q2：通过个性化 AI 推荐，把平均订单价值提升 20%
     - Q2：帮助运营人员监控所有系统，将仪表盘加载时间减少 80%

5. **组织输出**：按以下内容呈现转化后的路线图：
   - 按季度/阶段列出原始举措
   - 每项举措的结果陈述
   - 用于指示成功的关键指标
   - 依赖关系或排序说明

6. **补充战略背景**：针对整体路线图，补充：
   - 结果如何与公司战略对齐
   - 关于客户需求的关键假设
   - 灵活的发布窗口（按季度，而非具体日期）

7. **保存输出**：如果内容较多，保存为 markdown 文档：`Outcome-Roadmap-[year].md`

## 注意事项

- 结果应当可检验、可衡量
- 多个产出可能达成同一个结果；关注结果，而不是功能清单
- 结果导向路线图对变化更有韧性——拥抱灵活性
- 如果不确定某个功能驱动了什么结果，就追问「那又怎样？」，直到触及真实的客户/业务价值
