# 任务故事

使用「When [situation], I want to [motivation], so I can [outcome]」格式创建任务故事。生成的故事带有详细的验收标准，聚焦用户所处的情境与期望的结果。

**适用场景：** 编写任务故事、表达用户情境与动机、创建 JTBD 风格的待办项，或关注用户上下文而不是角色。

**参数：**
- `$PRODUCT`：产品或系统名称
- `$FEATURE`：要拆解为任务故事的新功能
- `$DESIGN`：设计文件链接（Figma、Miro 等）
- `$CONTEXT`：用户情境或任务场景

## 分步流程

1. **识别触发需求的用户情境**
2. **定义**用户行为背后的**动机**
3. **厘清**用户想要达成的**结果**
4. **应用 JTBD 框架：** 关注任务，而不是角色
5. **创建验收标准**，用于验证结果确实达成
6. **使用可观察、可衡量的表述**
7. **关联设计稿**或原型
8. **输出任务故事**，并附上详细验收标准

## 故事模板

**标题：** [任务结果或成果]

**描述：** 当 [情境] 时，我想要 [动机]，这样我就能 [结果]。

**设计：** [设计文件链接]

**验收标准：**
1. [情境被正确识别]
2. [系统支持所需的动机]
3. [进度或反馈可见]
4. [结果被高效达成]
5. [边界情况得到妥善处理]
6. [集成与通知正常工作]

## 任务故事示例

**标题：** 跟踪每周零食开销

**描述：** 当我为每周的零食零花钱做规划时（情境），我想快速看到目前为止已经花了多少（动机），这样我就能确保在周末之前不会把钱花光（结果）。

**设计：** [Figma 链接]

**验收标准：**
1. 展示支出摘要，包含「每周支出概览」区块
2. 记录支出时实时更新
3. 进度指示（进度条显示每周预算的 0-100%）
4. 剩余预算高亮显示，使用醒目颜色
5. 详细支出日志，按类别拆分
6. 预算达到 80% 阈值时通知
7. 周四晚达到 90% 时发送周末专属提醒
8. 可轻松访问并导航到详细拆分

## 输出交付物

- 该功能完整的一组任务故事
- 每个故事都遵循「When...I want...so I can」格式
- 6-8 条聚焦结果的验收标准
- 故事强调用户情境与动机
- 清晰关联设计与原型
