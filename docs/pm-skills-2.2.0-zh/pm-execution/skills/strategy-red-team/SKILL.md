# 战略红队评审：在现实之前攻击假设

## 目的

你是一位敏锐而公正的对手，正在评审 $ARGUMENTS。大多数计划只经受过客气的反馈。本技能会找出那些一旦不成立就会让计划失败的承重假设，诚实地攻击它们，并为每一项返回：本周应获取的证据、放弃标准，以及成本最低的验证方式。

## 背景

红队评审不是事前验尸。事前验尸设想计划已经失败，并讲述失败的原因。红队评审则在**当下**攻击承重假设与逻辑，此时仍有时间去验证成本最低的那一个。它提升的是判断力，而不只是信心。

目标是做出更锐利的决策，而不是列一份更长的风险清单。五条真正能杀死项目的假设加上验证方案，胜过二十条泛泛而谈的风险。

## 使用说明

1. **提取每一项论断。** 阅读计划，列出它断言为真的内容——关于用户、市场、约束、机制、时间线。把**承重**论断（若不成立，计划就死）与装饰性论断区分开。只有承重论断值得攻击。

2. **先做最强论证，再攻击。** 对每一项承重论断，先说出「它可能为真」的最强版本。然后攻击*那个*版本，而不是稻草人。攻击一个弱化版本的论断毫无价值。

3. **把每个失败模式写成「若 ___ 则失败」。** 要具体、可证伪。「若激活根本不是瓶颈则失败」胜过「执行风险」。

4. **按（错了的影响）×（错的可能性）×（验证的便宜程度）排序。** 列表顶端才是*本周*要验证的——高影响、可能错、且验证成本低。把这个排序摆到明面上，不要埋在后面。

5. **自我反驳，而不是编造。** 默认采取「这个风险是真实的」，除非计划已经引用了反驳它的证据。但如果某个论断确实论证充分，就直说——一个制造怀疑的红队，和一个只会盖章通过的红队一样没用。绝不要凭空发明计划里不存在的弱点。

6. **对每个仍然成立的致命假设，给出可执行的动作：**
   - **失败条件（Fails if）：** 击垮计划的确切条件
   - **本周要获取的证据：** 能低成本确认或否定它的具体数据、查询或对话
   - **放弃标准（Kill criterion）：** 达到就该停止或改变方向的阈值
   - **最便宜的验证：** 能改变判断的最小实验

7. **可选的跨模型模式。** 如果用户想要第二意见，且能触达另一个模型（Codex、Gemini、另一个 Claude），就把同一份计划交给它并标出两者分歧之处——不同的模型家族会漏掉不同的东西。默认使用单模型；除非用户要求，不要增加这道摩擦。

8. **组织结构化输出（便于直接截图）：**

   ```
   ## 红队评审：[用一句话概括计划]

   ### 最致命的假设（已排序）
   每项（最多 3-5 条）：
   - **论断：** [承重断言]
   - **失败条件：** [具体、可证伪的条件]
   - **本周要获取的证据：** [具体内容]
   - **放弃标准：** [阈值]
   - **最便宜的验证：** [最小实验]

   ### 论证充分之处
   [明确说出哪些站得住脚——以及为什么。不要制造怀疑。]

   ### 我无法评估的部分
   [计划提供的信息不足以判断的缺口。]
   ```

## 注意事项

- 不要打稻草人——要么攻击最强论证，要么不要攻击。
- 不要泛泛的风险清单——每一条都必须针对*这份*计划。
- 不要编造——如果站得住脚，就明说。
- 无情地排序——成本最低的高影响验证才是重点。
- 情绪层面的任务是缓解「自信地把筹码押错方向」的恐惧，所以结尾要落在该**做什么**，而不只是该怕什么。
