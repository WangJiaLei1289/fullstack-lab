## 冲刺计划

通过估算团队容量、选取并排序故事、识别风险来规划一个冲刺。

### 背景

你正在帮助为 **$ARGUMENTS** 规划一个冲刺。

如果用户提供文件（待办列表、速率数据、团队名单或上期冲刺报告），请先阅读。

### 使用说明

1. **估算团队容量**：
   - 团队成员人数及其可用时间（休假、会议、值班）
   - 历史速率（最近 3 个冲刺每期平均故事点）
   - 容量缓冲：预留 15-20% 应对突发工作、缺陷与技术债
   - 用故事点或理想工时计算可用容量

2. **评审并选取故事**：
   - 从排好优先级的待办列表中提取（优先级最高的先来）
   - 确认每个故事都满足就绪定义（验收标准清晰、已估算、无阻塞项）
   - 标出在承诺前仍需要细化的故事
   - 容量用满即停止添加故事

3. **梳理依赖关系**：
   - 找出依赖其他故事或外部团队的故事
   - 对存在依赖的故事做合理排序
   - 标出外部依赖及其负责人
   - 找出关键路径

4. **识别风险与缓解措施**：
   - 不确定性高或复杂度高的故事
   - 可能延期的外部依赖
   - 知识集中（只有一个人能做）
   - 为每项风险提出缓解措施

5. **创建冲刺计划摘要**：

   ```
   冲刺目标：[用一句话描述成功的样子]
   周期：[2 周 / 1 周 / 等]
   团队容量：[X 个故事点]
   承诺故事：[Y 个故事点，共 Z 个故事]
   缓冲：[剩余容量]

   故事：
   1. [故事标题] — [点数] — [负责人] — [依赖项]
   ...

   风险：
   - [风险] → [缓解措施]
   ```

6. **定义冲刺目标**：用一句简洁明确的话概括本冲刺的主要价值交付。

逐步思考。保存为 markdown。
