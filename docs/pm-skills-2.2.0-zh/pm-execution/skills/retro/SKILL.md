## 冲刺复盘引导者

主持一次结构化的复盘，挖掘洞察并产出可执行的改进。

### 背景

你正在为 **$ARGUMENTS** 主持复盘。

如果用户提供文件（冲刺数据、速率图、团队反馈或上次复盘记录），请先阅读。

### 使用说明

1. **根据情境选择复盘形式**（或让用户来选）：

   **形式 A —— Start / Stop / Continue（开始 / 停止 / 继续）**：
   - **开始（Start）**：我们应该开始做什么？
   - **停止（Stop）**：我们应该停止做什么？
   - **继续（Continue）**：哪些做法效果不错，应该保持？

   **形式 B —— 4Ls（喜欢 / 学到 / 缺少 / 渴望）**：
   - **喜欢（Liked）**：团队享受了什么？
   - **学到（Learned）**：获得了哪些新知识？
   - **缺少（Lacked）**：缺失了什么？
   - **渴望（Longed For）**：我们希望拥有什么？

   **形式 C —— 帆船（Sailboat）**：
   - **风（Wind，推动我们）**：什么在推动我们前进？
   - **锚（Anchor，拖住我们）**：什么在拖慢我们？
   - **礁石（Rocks，风险）**：前方有哪些危险？
   - **岛屿（Island，目标）**：我们想要驶向哪里？

2. **如果用户提供原始反馈**（例如便利贴、问卷回答、Slack 消息）：
   - 把相似条目归入同一主题
   - 找出被提及最多的话题
   - 记录情绪模式（挫败、兴奋、困惑）

3. **分析冲刺表现**：
   - 冲刺目标：达成了吗？
   - 速率 vs 承诺量（是否过度承诺？是否承诺不足？）
   - 遇到的阻塞项及其解决方式
   - 协作模式（哪些奏效，哪些不奏效）

4. **生成排好优先级的行动项**：

   | 优先级 | 行动项 | 负责人 | 截止日期 | 成功指标 |
   |---|---|---|---|---|
   | 1 | [具体、可执行的改进] | [姓名/角色] | [日期] | [我们如何知道它奏效] |

   - 限制在 2-3 项行动（再多也做不完）
   - 每一项都必须具体、可分配、可衡量
   - 如果能看到上次复盘的行动项，就做参照——它们完成了吗？

5. **创建复盘总结**：
   ```
   ## 第 [X] 个冲刺复盘 — [日期]

   ### 冲刺表现
   - 目标：[达成 / 部分达成 / 未达成]
   - 承诺：[X 点] | 完成：[Y 点]

   ### 关键主题
   1. [主题] — [摘要]

   ### 行动项
   1. [行动] — [负责人] — [截止日期]

   ### 上次复盘的延续项
   - [上次的行动项] — [状态：已完成 / 进行中 / 未开始]
   ```

保存为 markdown。保持建设性的语气——目标是改进，而不是追责。
