# 测试场景

根据用户故事创建完整的测试场景，包含测试目标、起始条件、用户角色、分步操作与预期结果。

**适用场景：** 编写 QA 测试用例、创建测试计划、定义验收测试场景，或验证用户故事的实现。

**参数：**
- `$PRODUCT`：产品或系统名称
- `$USER_STORY`：要测试的用户故事（标题与验收标准）
- `$CONTEXT`：额外的测试上下文或约束

## 分步流程

1. **审阅用户故事**与验收标准
2. **定义测试目标** —— 要验证的具体行为
3. **确定起始条件** —— 系统状态、数据准备、配置
4. **识别用户角色** —— 由谁执行测试操作
5. **创建测试步骤** —— 把交互逐步拆解
6. **定义预期结果** —— 每一步之后可观察到的结果
7. **考虑边界情况** —— 无效输入、边界条件
8. **输出详细测试场景** —— 可直接交给 QA 执行

## 示例测试场景

**测试场景：** 在产品页查看「最近浏览」商品

**测试目标：** 验证「最近浏览」区块正确展示，并排除当前商品。

**起始条件：**
- 用户已登录，或已启用浏览器历史记录
- 用户在当前会话中已浏览至少 2 个商品
- 用户当前所在的商品页与之前浏览过的商品不同

**用户角色：** 线上购物者

**测试步骤：**
1. 打开任意商品页 → 页面底部应出现包含此前浏览商品的区块
2. 滚动到页面底部 →「最近浏览」区块可见，并展示商品卡片
3. 检查商品缩略图 → 图片、标题与价格显示正确
4. 检查当前商品 → 当前商品**不会**出现在最近浏览列表中
5. 点击某个商品卡片 → 用户跳转到对应的商品页

**预期结果：**
- 仅在浏览过至少 1 个商品后，「最近浏览」区块才出现
- 区块展示 4-8 张商品卡片，信息完整
- 列表中已排除当前商品
- 每张卡片显示「X 分钟/小时前浏览」时间戳
- 点击卡片能跳转到正确的商品页
- 性能：区块在 2 秒内加载完成

## 输出交付物

- 针对每条验收标准的完整测试场景
- 与用户故事意图一致的清晰测试目标
- 详细的分步测试操作
- 每一步之后可观察的预期结果
- 边界情况与错误场景的覆盖
- 可直接交给 QA 团队执行与存档
