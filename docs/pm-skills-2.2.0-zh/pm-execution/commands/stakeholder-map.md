# /stakeholder-map —— 利益相关方地图与沟通计划

识别项目的所有利益相关方，按影响力和兴趣度进行标注，并生成沟通计划，确保正确的人在正确的时间获得正确的信息。

## 调用方式

```
/stakeholder-map New analytics platform launch
/stakeholder-map Pricing model change affecting all customers
/stakeholder-map [upload a project brief or org chart]
```

## 工作流程

### 第 1 步：理解计划内容

询问：
- 项目或计划是什么？
- 目前处于哪个阶段？（规划、构建、发布、发布后）
- 你已经知道的明显利益相关方有哪些？
- 是否有需要留意的政治敏感因素？

### 第 2 步：识别利益相关方

头脑风暴用户可能没考虑到的利益相关方：
- **内部**：工程、设计、QA、数据、法务、财务、市场、销售、支持、管理层
- **外部**：客户、合作伙伴、供应商、监管机构、董事会成员
- **常被遗漏**：相邻团队、值班工程师、客户成功、文档团队

### 第 3 步：映射到权力 × 兴趣矩阵

应用 **stakeholder-map** 技能：

把每个利益相关方放入对应象限：

```
                    高兴趣
                         │
    保持满意             │      重点管理
    （高权力，           │      （高权力，
     低兴趣）            │        高兴趣）
                         │
   ──────────────────────┼──────────────────────
                         │
    监控                 │      保持知情
    （低权力，           │      （低权力，
     低兴趣）            │        高兴趣）
                         │
                    低兴趣
```

### 第 4 步：生成沟通计划

```
## 利益相关方地图：[计划名称]

### 利益相关方矩阵
| 利益相关方 | 角色 | 权力 | 兴趣 | 象限 | 立场 |
|------------|------|-------|----------|----------|--------|

### 沟通计划

#### 重点管理（高权力、高兴趣）
| 利益相关方 | 渠道 | 频率 | 内容 | 负责人 |
|------------|---------|-----------|---------|-------|

#### 保持满意（高权力、低兴趣）
| 利益相关方 | 渠道 | 频率 | 内容 | 负责人 |
|------------|---------|-----------|---------|-------|

#### 保持知情（低权力、高兴趣）
| 利益相关方 | 渠道 | 频率 | 内容 | 负责人 |
|------------|---------|-----------|---------|-------|

#### 监控（低权力、低兴趣）
[最小化沟通 — 仅纳入广泛更新]

### 潜在冲突
[利益相关方利益可能冲突之处 — 附缓解策略]

### 升级路径
[决策被阻塞时应找谁]

### RACI 矩阵
| 决策领域 | 负责执行（Responsible） | 最终担责（Accountable） | 被咨询（Consulted） | 被通知（Informed） |
|--------------|-------------|-------------|-----------|----------|
```

保存为 markdown。

### 第 5 步：提供后续步骤

- 「要我 **为『重点管理』群体起草第一份利益相关方更新** 吗？」
- 「要我 **为关键利益相关方的沟通准备会议简报** 吗？」
- 「要我 **把沟通节奏设为可复用的检查清单** 吗？」

## 说明

- 「重点管理」象限是 PM 花费最多政治资本的地方 — 把这些关系处理好
- 「立场」（支持、中立、反对）有助于确定把关系建设精力优先投向哪里
- 不要忘记下游利益相关方：支持、文档和销售赋能团队常常对发布感到意外
- 随着项目推进持续更新地图 — 利益相关方的兴趣会随项目阶段变化
