# /meeting-notes —— 会议总结

把原始的会议逐字稿或粗略笔记转化为清晰、结构化的会议纪要，记录决议并分配行动项。

## 调用方式

```
/meeting-notes [paste transcript]
/meeting-notes [upload transcript file, audio summary, or notes]
```

## 工作流程

### 第 1 步：接收逐字稿

接受任何格式：
- 完整逐字稿（来自 Otter、Fireflies、Google Meet、Zoom 等）
- 会议期间记录的粗略笔记
- 转写工具生成的音频摘要或会议回顾
- 多种输入（例如逐字稿 + 用户自己的笔记）

如果输入信息稀疏，就基于现有内容推进，并指出缺口。

### 第 2 步：提取并结构化

应用 **summarize-meeting** 技能：

解析内容，识别：
- **参会人**：谁到场（从自我介绍、说话人标签或提及中提取）
- **讨论主题**：主要议程项或对话线索
- **做出的决议**：明确达成的共识或结论
- **行动项**：分配的任务，若提及则包含负责人和截止日期
- **未决问题**：需要后续跟进、尚未解决的事项
- **关键原话**：值得逐字保留的重要表述
- **背景**：会议类型、项目及背景信息

### 第 3 步：生成会议纪要

```
## 会议纪要

**日期**：[已知则填写]
**参会人**：[姓名/角色]
**会议类型**：[站会、规划、评审、1:1、利益相关方会议等]
**主题**：[主要议题]

### 摘要
[用 3-5 句话概括讨论了什么、得出了什么结论]

### 关键决议
1. **[决议]** — [背景与理由]
2. ...

### 行动项
| # | 行动 | 负责人 | 截止日期 | 状态 |
|---|--------|-------|----------|--------|

### 讨论亮点
**[主题 1]**：[要点、不同观点、结论]
**[主题 2]**：[要点、不同观点、结论]

### 未决问题
- [问题] — 需要 [人员/团队] 提供意见

### 后续步骤
- [接下来会发生什么]
- 下次会议：[如有提及]
```

保存为 markdown。

### 第 4 步：提供后续动作

- 「要我把这份纪要 **通过邮件发给参会人** 吗？」
- 「要我从行动项中 **创建工单** 吗？」
- 「要我基于已达成的决议 **起草一份利益相关方更新** 吗？」

## 说明

- 决议是最有价值的输出 — 确保每项决议都被清晰记录
- 没有负责人的行动项没有意义 — 如果未提及负责人，要指出这一点
- 摘要保持简洁 — 没参会的人应在 30 秒内了解要点
- 如果逐字稿很长（会议超过 60 分钟），在完整纪要之前先给一个 TL;DR
- 区分「讨论过」和「已决定」 — 很多话题只是被探讨，并未得出结论
