# /red-team-prd —— 在现实之前先攻击计划

大多数计划只是经受住了礼貌的反馈。本命令找出会让你的计划失败的假设，坦诚地攻击它们，并为每个假设给出成本最低的测试 — 这样你就能在本周而非发布时终止一个坏赌注。

## 调用方式

```
/red-team-prd [paste or upload a PRD, roadmap, or strategy]
/red-team-prd Prioritize AI onboarding — activation is our bottleneck
/red-team-prd the current doc
```

## 工作流程

### 第 1 步：接收计划

以任何形式接收 — PRD、路线图、战略备忘录、一句话赌注，或上传的文档。如果用户说「当前文档」，就使用上下文中的那份文档。

### 第 2 步：发起红队评审

应用 **strategy-red-team** 技能：

- 提取每一条论断；只保留**承重**的论断（不成立则计划失败）。
- **先为每条论断构造最强版本（steelman），再攻击这个最强版本** — 不要攻击稻草人。
- 把每种失效模式写成「**如果 ___，则失败**」。
- 按**（错了的影响）×（错的可能性）×（验证的便宜程度）**排序。
- 除非计划提供了反驳证据，否则默认「风险是真实的」 — 但要**明说哪些地方论证充分**，绝不捏造弱点。

### 第 3 步：返回输出

```
## 红队评审：[用一句话描述计划]

### 最致命的承重假设（已排序）
- **论断：** [承重断言]
  - **如果 ___，则失败：** [具体且可证伪]
  - **本周需要获取的证据：** [具体]
  - **终止判据：** [阈值]
  - **成本最低的测试：** [最小实验]
[最多 3–5 条]

### 论证充分的部分
[明确写出来 — 不要人为制造疑虑。]

### 我无法评估的部分
[计划提供的信息不足以判断的地方。]
```

### 第 4 步：提供后续步骤

- 「要我 **把最致命的承重假设转成实验**，让你本周就能跑吗？」
- 「要我 **做一次事前验尸** 作为补充 — 想象它已经失败，倒推路径吗？」
- 「要我 **重写风险最高的部分**，以处理经受住攻击的内容吗？」

## 说明

- 先给排序 — 成本最低、影响最大的测试才是重点。
- 五条真实的承重假设配上测试，胜过二十条泛泛的风险。要毫不留情地裁剪。
- 与 `/pre-mortem` 不同：事前验尸是事后叙述失败；红队评审攻击的是当下的假设，并直接给你测试。
- 如果计划确实很强，最有价值的输出就是如实说明 — 并指出仍然值得验证的那一件事。
- 如果要做第二意见的复核，在引入跨模型摩擦前先询问用户；不同模型家族会漏掉不同的东西，但大多数计划并不需要。
