# /plan-okrs —— 团队 OKR 规划

生成结构良好的 OKR，把团队工作与公司战略连接起来。产出 3 组 OKR，包含定性目标和定量关键结果。

## 调用方式

```
/plan-okrs Growth team Q2 — company goal is 50% ARR increase
/plan-okrs Onboarding squad aligned to "improve activation rate"
/plan-okrs [upload company OKRs or strategy doc]
```

## 工作流程

### 第 1 步：收集上下文

询问用户：
- 这些 OKR 面向哪个团队或产品领域？
- 时间周期是什么？（按季度是标准做法，也可以是年度或自定义）
- 这些 OKR 应向上对齐到哪些公司级目标？
- 上个季度发生了什么？（达成、未达成、经验教训）
- 有哪些约束条件或已知的优先级？

接受用户上传的公司 OKR 或战略文档。

### 第 2 步：生成 OKR

应用 **brainstorm-okrs** 技能：

- 创建 3 组 OKR（每个目标配 3-5 个关键结果）
- **目标**：定性、鼓舞人心、有野心但可实现、面向行动
- **关键结果**：定量、可衡量、有时限、有明确负责人
- 确保 OKR 与公司目标对齐，且关联关系清晰可见
- 平衡先行指标（活动量）与滞后指标（结果）

### 第 3 步：校验质量

对照最佳实践检查每组 OKR：
- 目标是否鼓舞人心？（你会围绕它召集团队吗？）
- 关键结果是否可衡量？（能否用数据而非主观判断确认完成？）
- 目标是否既有野心又不至于打击士气？（达成 70% 即为标定得当）
- 每个目标是否有 3-5 个关键结果？（更多意味着失焦）
- 关键结果是否避免了博弈空间？（例如「上线 5 个功能」会激励为了数量而交付劣质内容）

指出任何问题并给出改进建议。

### 第 4 步：呈现并迭代

```
## 团队 OKR：[团队名称] — [周期]

**对齐到**：[公司目标]

### 目标 1：[鼓舞人心的定性表述]
| # | 关键结果 | 基线 | 目标值 | 负责人 |
|---|-----------|----------|--------|-------|
| KR1 | [可衡量的结果] | [当前] | [目标] | [团队/个人] |
| KR2 | ... | ... | ... | ... |
| KR3 | ... | ... | ... | ... |

### 目标 2：[鼓舞人心的定性表述]
[相同格式]

### 目标 3：[鼓舞人心的定性表述]
[相同格式]

### 对齐关系图
公司目标 → 团队目标 → 关键结果 → 预期影响

### 评分指南
- 0.0-0.3：明显未达标 — 深入调查并吸取教训
- 0.4-0.6：有进展但未达预期
- 0.7-0.9：标定得当的挑战目标 — 这就是目标区间
- 1.0：要么完美达成，要么目标不够有野心

### 检查节奏
- **每周**：对每个关键结果做快速红黄绿灯更新
- **季度中期**：深度复盘，如果上下文变化则调整目标
- **季度末**：评分、反思，并输入下一季度
```

提供以下选项：
- 「要我 **调整野心程度** — 让目标更激进或更保守吗？」
- 「要我 **创建一个指标看板** 来跟踪这些 OKR 吗？」
- 「要我 **起草一份利益相关方更新**，介绍这些 OKR 吗？」

## 说明

- OKR 应描述结果而非产出（「将激活率提升 20%」而不是「上线新手引导改版」）
- 如果用户没有公司 OKR，帮他们从产品战略或业务目标中推导团队目标
- 每个团队每季度最多 3 个目标 — 更多意味着更不聚焦
- 关键结果应是挑战目标 — 如果你确信一定能达成，说明野心不够
- 指出任何可能被博弈的关键结果，并建议一个反向指标
