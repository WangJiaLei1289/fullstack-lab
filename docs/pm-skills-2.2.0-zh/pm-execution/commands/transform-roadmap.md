# /transform-roadmap —— 结果导向路线图

把一份计划功能清单或产出导向的路线图改写成结果导向的路线图，传达的是「为什么」而不是「做什么」。

## 调用方式

```
/transform-roadmap [paste your feature list or roadmap]
/transform-roadmap [upload a roadmap doc, spreadsheet, or screenshot]
```

## 工作流程

### 第 1 步：接收当前路线图

接受任何格式：
- 功能清单或待办项
- 路线图文档（Now/Next/Later、按季度、时间线）
- 电子表格或甘特图导出
- 路线图工具的截图

解析每一项，提取：功能名称、描述、目标日期/时间范围以及相关背景。

### 第 2 步：理解战略背景

询问：
- 这一周期的产品目标或 OKR 是什么？
- 这份路线图的受众是谁？（高管、工程、客户、董事会）
- 你偏好哪种格式？（Now/Next/Later、按季度、时间线）

### 第 3 步：逐项转换

应用 **outcome-roadmap** 技能：

对路线图上的每项功能/产出：
1. 识别它试图实现的**用户结果或业务结果**
2. 改写为结果陈述：「[动词] [指标/体验]，面向 [用户细分]」
3. 把服务于同一结果的功能归入同一个举措
4. 为每个结果添加成功指标

**改写前后示例：**
- 「构建 SSO 集成」→「降低企业客户的新手引导摩擦 — 目标：企业账号的首次价值达成时间缩短 50%」
- 「重新设计仪表盘」→「帮助重度用户更快找到洞察 — 目标：洞察时间减少 30%」
- 「增加 CSV 导出」→「让团队能在产品之外共享数据 — 目标：报表分享量提升 25%」

### 第 4 步：生成转换后的路线图

```
## 结果导向路线图：[产品] — [周期]

**战略主题**：[2-3 个高层主题]

### Now（当前季度）
**主题：[战略主题]**
| 结果 | 成功指标 | 关键举措 | 状态 |
|---------|---------------|----------------|--------|

### Next（下个季度）
**主题：[战略主题]**
| 结果 | 成功指标 | 关键举措 | 置信度 |
|---------|---------------|----------------|------------|

### Later（未来）
**主题：[战略主题]**
| 结果 | 成功指标 | 关键举措 | 依赖项 |
|---------|---------------|----------------|-------------|

### 转换说明
| 原始功能 | 转换后的结果 | 这样表述的原因 |
|-----------------|--------------------|-----------------|

### 变化了什么
[路线图叙事如何转变的总结]
```

保存为 markdown 文件。

### 第 5 步：评审

提供：
- 「要我 **为每个结果补充 OKR 对齐关系** 吗？」
- 「要我 **起草这份路线图的利益相关方演示文稿** 吗？」
- 「要我 **识别 Now 事项的风险** 吗？」

## 说明

- 结果应当可衡量，并有清晰的「完成」状态
- 多个功能可以映射到同一个结果 — 这是特性，不是缺陷
- 如果某个产出并不清楚服务于哪个结果，标出来让用户论证或降低优先级
- 受众很重要：面向高管的路线图应只写结果，面向工程的路线图可以在每个结果下列出交付物
- 「Later」事项应更不具体 — 只有结果，不承诺解决方案
