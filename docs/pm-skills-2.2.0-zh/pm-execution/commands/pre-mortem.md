# /pre-mortem —— 发布前风险分析

想象你的发布已经失败。现在倒推原因。本命令应用「老虎 / 纸老虎 / 房间里的大象」框架，浮出真实风险并制定缓解计划。

## 调用方式

```
/pre-mortem [paste or upload a PRD, launch plan, or feature spec]
/pre-mortem We're launching a self-serve billing portal next month
```

## 工作流程

### 第 1 步：接收计划

接受任何格式：PRD、功能规格、发布计划、项目简报或口头描述。提供的细节越多，风险分析越精准。

### 第 2 步：识别风险

应用 **pre-mortem** 技能：

想象产品已经发布并失败。按类别生成风险：
- **技术**：性能、可扩展性、集成故障、数据问题
- **用户**：采用障碍、可用性问题、期望落空
- **业务**：收入影响、竞品反应、市场时机
- **运营**：支持负载、文档缺口、培训需求
- **依赖**：第三方服务、跨团队交接、监管

### 第 3 步：对风险分类

对每个风险归类：

**老虎（Tigers）** — 真实、实质性的风险，可能导致失败
- 评估严重程度：阻塞发布 / 快速跟进 / 持续跟踪
- 对阻塞发布的老虎：必须立即缓解
- 对快速跟进的老虎：计划在发布后的第一个冲刺内解决
- 对持续跟踪的老虎：保持监控，但不延迟发布

**纸老虎（Paper Tigers）** — 看起来吓人但被夸大的风险
- 说明为什么这个担忧是可控的
- 指出在什么条件下它会变成真正的老虎

**房间里的大象（Elephants）** — 团队心知肚明却避而不谈的风险
- 揭示政治、组织或令人不适的风险
- 以建设性方式呈现，并给出建议的对话切入点

### 第 4 步：生成事前验尸报告

```
## 事前验尸：[功能/发布]

**日期**：[今天]
**状态**：[草稿 / 已评审]

### 风险汇总
- **老虎**：[数量]（[阻塞发布]、[快速跟进]、[持续跟踪]）
- **纸老虎**：[数量]
- **房间里的大象**：[数量]

### 阻塞发布的老虎
| # | 风险 | 可能性 | 影响 | 缓解措施 | 负责人 | 截止日期 |
|---|------|-----------|--------|-----------|-------|----------|

### 快速跟进的老虎
| # | 风险 | 可能性 | 影响 | 计划应对 | 负责人 |
|---|------|-----------|--------|-----------------|-------|

### 持续跟踪的老虎
[发布后需监控的风险及触发条件]

### 纸老虎
[看似严重但可控的担忧 — 附理由]

### 房间里的大象
[团队应当讨论的、令人不适的真相]

### 发布/不发布检查清单
- [ ] 所有阻塞发布的老虎都已缓解
- [ ] 快速跟进计划已记录并分配
- [ ] 持续跟踪的老虎已有监控
- [ ] 回滚方案已定义
- [ ] 支持团队已了解情况
```

保存为 markdown。

### 第 5 步：提供后续步骤

- 「要我 **更新 PRD**，补充风险缓解措施吗？」
- 「要我针对风险最高的部分 **创建测试场景** 吗？」
- 「要我根据这些发现 **起草一份发布检查清单** 吗？」

## 说明

- 最好的事前验尸发生在计划完成 80% 时 — 早到足以调整方向，晚到足够有实质内容
- 要追问到显而易见的风险之外 — 最危险的风险是没人提到的那一个
- 房间里的大象是最高价值的输出 — 揭示团队避而不谈的东西
- 对每只老虎，缓解措施应具体、可指派，而不是「小心一点」
- 如果事前验尸暴露出太多阻塞发布的老虎，建议推迟发布或分阶段发布
