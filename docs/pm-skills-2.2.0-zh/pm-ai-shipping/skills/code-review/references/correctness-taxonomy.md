# 正确性分类法——十三种透镜，各自的检测线索

*正确性子场景的参考文件——`code-review` 技能的核心。性能与安全子场景在本文件旁边各有自己的文件。*

这些是相互重叠的诊断透镜，不是分类方案，也不是配额。每个条目都说明**如何检测它**，因为光有一个类别名，不会改变评审者去看什么。

第 1、2 号透镜是强评审者——无论人还是机器——最常漏掉的，也是仅有的两个值得做显式强制探测、而不只是通读一遍的透镜。两者都是*看*的失败，而不是判断的失败：在每个参与方那里，代码读起来都很合理，缺陷只存在于它们之间的关系中。

---

### 1. 权威源对账
沿着一个提议值穿过校验、规范化、协商或提交。找出仍然由**提议**推导而来的下游状态，而权威源可能合法地返回不同的东西。检查对账是否发生在第一次有后果的使用*之前*。

> **被请求的值不是被应用的值。** 凡是系统能说「我听到了，这是我实际做的」，那个回复就是权威——请求不是。

**探测：** 构造一次执行，让实际生效的答案与请求的答案不同，然后追问：哪一块存储状态、哪一个 UI、哪一次后续调用、哪一行日志仍然带着那个请求。

### 2. 标识与关联
追踪一个操作的结果如何找到它归属的实体。确认关联键在重叠操作、重排、移除和复用情况下的**唯一性、稳定性和生命周期**。一个标签、一个索引、一个位置或到达顺序之所以可疑，恰恰是因为其中某项可能失效。

**探测：** 并发运行两个操作，并让它们乱序完成。然后移除其中一个（在其执行途中），并复用它占用的槽位。

### 3. 新鲜度与世代
标出每一个在 yield、await、回调、定时器或释放锁之前捕获的值。确定在它被使用之前可能发生什么变化，以及该操作是否仍然指向预期的实体*和版本*。检查代码对过期结果实际做了什么——忽略、应用，还是静默应用。

### 4. 生命周期与派生状态
比较每一条可达的构建、替换、恢复、重置、失败和终止路径。找出那些在一条路径上被正确重建、在另一条路径上被错误保留的派生字段或缓存决策。两条本应最终进入等价状态的路径，和其他任何约定一样，也是一种约定。

### 5. 原子性与部分失败
在每个失败点和取消点切分多效果操作。部分状态是否被允许、可恢复且被准确报告？找出在所需效果持久化之前就报告成功的情况。

### 6. 重放与效果基数
跟随重试、重复投递、重复回调和重新进入效果。把实际的投递保证与所需的效果次数作比较——尤其当某个效果要花钱、要发消息或会改动共享总量时。检查去重范围、生命周期，以及部分成功之后的行为。

### 7. 组合与优先级
追踪独立产生的片段穿过合并、归约、排序和分发。把实际的覆盖与选择规则同预期的权威或优先级作比较——包括在合并*之后*应用、悄悄改变其顺序或键的转换。

### 8. 边界、单位与记账
跟随计数、长度、偏移、容量和总量穿过每一次转换。检查空与边界情况、溢出、舍入，以及计量与消费是否使用同一单位和同一表示。

### 9. 分帧与增量处理
把逻辑项边界与实际读、写、迭代器和回调边界作比较。测试被拆分的项、被合并的项、部分写入和提前终止。检查缓冲、刷新和收尾——尤其是最后一项。

### 10. 表示与信息丢失
把生产者能发出的值，与消费者所依赖的区分作比较。追踪往返和派生输出中消失掉的区分。**这是所检查的每个语料库中频率最高的一类**——无论植入的还是自然的——所以要多过几遍。

这类问题大多落在三种子形态上：

- **空值家族。** *待定（pending）*、*缺失（absent）*、*空（empty）*、*零（zero）*、*假（false）* 和 *失败（failed）* 是六种不同的状态，却极易彼此塌缩。一次失败的读取返回空结果；一个从未启动的资源被报告为已损坏；一个守卫排除了 `null` 却没排除 `undefined`；一个显式的 null 被当成字段缺失而跳过；字符串 `"false"` 落进了布尔值；像 `-1` 这样的哨兵值代表「没有答案」，随后又被计数。**探测：** 对每个可能缺失的值，枚举它实际上可能是六种中的哪一种，并检查消费者是否区分了要紧的那几种。
- **投影与字段集漂移。** 一个生产者——一次查询、一个 DTO、一个序列化器、一个映射器——不再发出某个字段，而消费者只是静默降级，并不报错。**探测：** 把生产者实际选择的字段集，与其消费者读取的每个字段作差集比较，包括嵌套投影和*渲染器*会碰到的字段。还要检查是否存在以生产者从未发出的名字读取字段的情况。
- **未解析的值被当作已解析的值存储。** 一个 promise、一个 future、一个惰性句柄或一个仍在加载的状态，被持久化或被比较，仿佛它就是已敲定的值。**探测：** 凡是值存在「尚未就绪」状态的地方，找出谁在没有检查的情况下读取它。

然后是那些常规维度：有符号与无符号、规范形式、精度、编码、相等语义。

**线索：** 一处类型转换、一个 `any`、一个非空断言或一处被压制的警告，位于边界上时，正是契约死掉的地方——这个标注之所以存在，恰恰是因为两侧不一致，而有人让编译器闭嘴，而不是去对账。把边界上每一个这类东西都当作候选。

### 11. 所有权、完成与进度
追踪谁可以变更、释放、取消和完成一个操作或资源。检查异常出口和相互竞争的终止路径，找出提前释放、缺少完成、死锁，以及所有权易手之后的使用。

### 12. 决策与分发
枚举有后果的谓词和分发表所对应的有意义状态与输入。把分支与有支撑的期望作比较：重叠条件、反转的判断、缺失的分支，以及兜底实际做了什么。检查当代码没有指定任何东西时，框架或语言提供的*默认值*——未被声明的默认值仍然是一个决策。

**要把可达性算进来，而不只是正确性。** 对每个有后果的分支，问是否有任何输入能到达它；对每个被调度或被注册的东西，问是否真有东西启动它。一个永远不可能为真的谓词、一个从未接上的处理器、一个输出永远到不了磁盘的写入者、一个调度器从未启动的任务，全都是读起来像完美正确代码的缺陷。它们在真实世界里很常见，在植入语料中几乎不存在，所以任何用植入缺陷训练出来的检查清单都不会提示你去看这里。

### 13. 验证与可观测性
跟随每一步*失败*时会发生什么，并追问什么能让这次失败变得可见。找出不可能失败的检查、度量的东西并非它声称要度量的判定器、被吞进成功路径的异常、跳过其对象的门禁，以及其缺失不会被任何东西发现的效果。一个永远通过的步骤，不是一个通过的步骤。

**探测：** 对系统声称的每一项保证，说出如果它不再成立会随之破掉的那个观察点。如果找不到，这项保证就是装饰性的。

> 这条透镜的存在源于证据上的一个缺口，而这个缺口值得说明。一个*植入的*缺陷在构造上就是可检测的——有人把它种进去，所以有人能找到它。因此静默失败在植入语料中系统性缺席，在真实的修复历史里却大量出现——在那些历史中，「而且没人注意到」是一句反复出现的话。不要让一张基准测试形状的清单说服你别看这里。

## 使用这些透镜

- 它们是有意重叠的。一个缺陷可以同时是第 1 号和第 3 号透镜；根因只报告一次。
- 在某条透镜下没有发现项，是有效结果。不要为了填表而制造一条。
- 在第 1、2 号透镜下什么都没找到，*只有*在你从未构造它们的探测时才值得再看一眼——通读一遍在这里可靠地什么都返回不了，而这恰恰就是那种失败模式。
- 这些透镜都不针对特定语言或框架。如果某条透镜看起来不适用，说明是系统的哪个性质使它不适用。
