# 子场景：安全评审

父引擎的一个特化。锚点变了，并且有一条反驳规则相对于正确性是**反过来的**——在与其他子场景一起运行本子场景之前，先读那一节。

**锚点：** 来源 → 信任边界 → 汇聚点（sink），且有攻击者控制来源。

被检验的约定，存在于一个组件*信任什么*与攻击者能*提供什么*之间。正确性问「这会发生吗」，安全问「有人能让它故意发生吗」——而对手会有意去构造那种不太可能发生的执行。

## 流程在哪里

`/security-audit-static` 拥有完整的专项流程——入口点映射、四条高价值路径、带攻击者与受害者检验的保留/丢弃规则、OWASP Top 10 覆盖兜底，以及高漏报检查清单。**运行它，而不是在这里复述。** 本文件存在，是为了说明当安全被选为代码评审的一个维度时有哪些变化，并提供当应用完全没有 Web 表面时仍然适用的那部分引擎。

## 通用内核

适用于 CLI、库、守护进程、构建工具——任何看不到 HTTP 处理器的东西。

- **信任边界**——数据从信任度较低的来源进入信任度较高上下文的每一个点：参数、环境、配置文件、标准输入、文件名、归档成员、网络响应、插件与扩展接口、反序列化的状态，以及模型输出。
- **汇聚点（sink）**——值在这里变成指令而不是数据：进程执行、动态求值、查询构造、路径解析、模板渲染、反序列化、出站请求、权限与角色写入，以及日志记录。
- **表示混淆导致的注入**——值按汇聚点的语法被解释，而不是当作不透明的数据。要针对*汇聚点*编码，而不是在输入处编码。这与正确性第 10 号透镜（表示与信息丢失）是同一个分歧，只是有对手在操纵它。
- **校验器/消费者差异**——检查与使用对值的含义看法不一致：未加锚点的匹配模式、前缀允许列表、只在一侧做的规范化、对一种表示做校验却对另一种表示执行。
- **失败时放行的路径（fail-open）**——错误、超时、取消、缓存未命中和边界分支，默认选择*允许*。正确性第 12 号透镜找到这些；安全决定它们的代价。
- **密钥与敏感数据被送往错误的地方**——日志、链路追踪、错误响应体、临时文件、崩溃转储，以及任何无特权的本地用户都能读到的东西。
- **权限与身份**——一个操作以哪个主体身份运行，检查与动作是否指向同一个对象，以及当它们不一致时会发生什么。

## 反转的反驳规则

在正确性下，一个只伤害触发它的人的缺陷仍然是缺陷。在安全下，它通常**不是**发现项：如果唯一的受害者就是攻击者本人，在他们自己的机器、账号、租户或数据上，且没有跨越任何共享系统或权限边界，就丢弃它。

那条反驳**被禁止**适用的例外——出站网络汇聚点、共享计费或配额、数据暴露、跨租户或跨主体流程，以及服务端执行或渲染——列在 `/security-audit-static` 里。用它的清单；不要自己发明一套。

**不要让两条规则互相渗透。** 在一次评审中同时运行两个维度时，按发现项把检验分开：一条作为安全发现项被丢弃的缺陷，仍可能是一条有真实后果的正确性发现项，并且应当按正确性来报告。

## 什么样的东西算安全发现项

父技能的五项要求，其中触发一项要按对抗视角来读：

1. 有支撑的义务——信任假设，以及是什么确立了它。
2. 可行的执行——**包括攻击者是谁、控制了什么。**
3. 具体的矛盾——未能守住的边界。
4. 可观察的后果——**指出受害者**，受害者不能只有攻击者。
5. 已审查的反论——汇聚点处真正的检查、一条不可达的路径、一个上游校验器，或一个并非危险的汇聚点。

发现项是代码评审结果，不是已确认的漏洞利用。要说明这一点。
