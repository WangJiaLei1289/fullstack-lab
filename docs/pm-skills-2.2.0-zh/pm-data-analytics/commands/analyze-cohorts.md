# /analyze-cohorts —— 同期群分析

以同期群为单位分析用户留存与参与度模式。上传你的数据或描述需求，获取留存曲线、功能采用趋势与可执行的洞察。

## 调用方式

```
/analyze-cohorts [上传一份用户行为数据的 CSV]
/analyze-cohorts 按获客渠道分组，分析 1-6 月注册用户的月度留存
/analyze-cohorts 帮我们为新版本新手引导设计一套同期群分析
```

## 工作流程

### 第 1 步：接收数据或定义分析

两条路径：
- **有数据**：用户上传含用户级数据的 CSV／表格（user_id、signup_date、activity_date、event_type 等）
- **无数据**：用户描述所需分析 → 生成 SQL 查询与分析框架

### 第 2 步：定义同期群

询问：
- 同期群由什么定义？（注册周／月、获客渠道、套餐层级、首次使用的功能）
- 留存事件是什么？（登录、核心动作、任意活动、购买）
- 时间粒度是什么？（按日、按周、按月）
- 时间范围是什么？

### 第 3 步：分析

应用 **cohort-analysis** 技能：

**若提供了数据：**
- 用 Python（pandas）处理数据，生成同期群表
- 计算每个同期群在每个周期的留存率
- 生成留存曲线
- 识别模式：同期群变好／变差、季节性效应、异常
- 对比各同期群的功能采用情况

**若只是在描述分析：**
- 设计同期群分析框架
- 生成用于抽取数据的 SQL 查询
- 创建用于分析的表格模板
- 定义指标与可视化方案

### 第 4 步：生成报告

```
## 同期群分析：[描述]

**日期**：[今天]
**同期群定义**：[例如：注册月份]
**留存事件**：[例如：完成一个项目]
**粒度**：[周／月]

### 留存表
| 同期群 | 规模 | 第 1 周 | 第 2 周 | 第 3 周 | ... | 第 12 周 |
|--------|------|--------|--------|--------|-----|---------|

### 关键发现
1. **[发现]** — [支撑数据]
2. ...

### 同期群对比
- **表现最好的同期群**：[哪个、为什么]
- **表现最差的同期群**：[哪个、为什么]
- **趋势**：[随时间变好／变差／平稳]

### 留存基准
| 周期 | 你的留存率 | 行业基准 | 差距 |
|--------|----------|-------------------|-----|

### 建议
1. [基于发现要调查或改变什么]
2. ...

### 后续查询
[用于进一步排查的 SQL 查询]
```

若提供了数据，把分析同时保存为 markdown 报告与 CSV／表格。

### 第 5 步：提供后续选项

- 「需要我按另一个维度**进一步切分**吗？」
- 「要不要基于这些留存阈值**设置指标告警**？」
- 「需要我**设计实验**来改善最弱同期群的留存吗？」

## 说明

- 同期群分析的成败取决于留存事件的定义——要推动用户给出有意义的行为，而不只是「登录过」
- 早期同期群常因首批用户带来的偏差而显得不同——对比时要说明这一点
- 若留存是用 Python 脚本算的，请保存脚本，方便用户用新数据重跑
- 季节性效应可能伪装成趋势——如果同期群差异可能是日历因素导致的，要指出来
