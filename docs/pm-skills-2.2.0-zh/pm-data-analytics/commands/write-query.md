# /write-query —— SQL 查询生成器

用自然语言描述你需要的数据，得到一条优化过的 SQL 查询。支持多种方言，也能从上传的文件中读取你的表结构。

## 调用方式

```
/write-query 给我最近 30 天的日活用户，按套餐层级拆分
/write-query 找出上月注册但从未完成新手引导的用户
/write-query [上传一份表结构图] 试用转付费的转化率按同期群分别是多少？
```

## 工作流程

### 第 1 步：理解问题

解析用户的自然语言请求，识别：
- 需要什么数据（指标、维度、筛选条件）
- 时间范围与粒度
- 分组与排序偏好
- 期望的输出形式（原始数据、聚合结果、排名）

### 第 2 步：确定表结构

如果有表结构（上传的图、DDL 或描述）：
- 把请求映射到具体的表与字段
- 识别必要的连接

如果没有提供表结构：
- 询问数据库类型（BigQuery、PostgreSQL、MySQL 等）
- 从问题推断一个合理的表结构，请用户确认
- 用常见的 SaaS 数据模型约定作为默认值

### 第 3 步：生成查询

应用 **sql-queries** 技能：

- 用正确的方言编写 SQL 查询
- 在可读性与性能之间做优化
- 加上注释解释关键逻辑
- 复杂查询用 CTE 提升可读性
- 处理边界情况（NULL、时区、重复数据）

### 第 4 步：呈现并迭代

```
## SQL 查询：[它做什么]

**方言**：[BigQuery / PostgreSQL / MySQL / 等]
**使用的表**：[列出]

### 查询
[带注释的 SQL 代码块]

### 这条查询返回什么
[输出说明：字段、行数、预期结果形态]

### 前提假设
- [对表结构的假设]
- [对业务逻辑的假设]

### 说明
- [大数据集下的性能考量]
- [已处理或已标注的边界情况]
```

提供选项：
- 「需要我**改一下**——加筛选、改分组、调整时间范围吗？」
- 「要不要**配一条相关指标的查询**？」
- 「需要我围绕这条查询**搭一个看板**吗？」
- 「需要这条查询的**同期群分析版**吗？」

## 说明

- SQL 里始终写注释——产品经理会把查询分享给分析师，对方需要理解意图
- 宁要可读，不要炫技——用 CTE 而不是嵌套子查询
- 对在大数据集上可能很慢的查询要指出来，并建议优化
- 如果请求含糊（例如「活跃用户」），请用户精确定义这个指标
- 如果用户不确定用的是哪种数据库，主动提供多个方言的版本
