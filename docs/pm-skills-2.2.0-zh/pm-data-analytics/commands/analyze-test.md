# /analyze-test —— A/B 测试分析

以统计严谨性评估实验结果，并把发现转化为清晰的产品决策：发布、延长还是停止。

## 调用方式

```
/analyze-test 对照组：4.2% 转化（n=5000），实验组：4.8% 转化（n=5100）
/analyze-test [上传测试结果 CSV]
/analyze-test [上传实验平台的截图]
```

## 工作流程

### 第 1 步：接收测试数据

接受任何格式：
- 汇总统计（各实验组的转化率、样本量）
- 原始事件数据（含 user_id、variant、converted、timestamp 的 CSV）
- 实验平台截图（Optimizely、LaunchDarkly 等）
- 对实验及结果的描述

### 第 2 步：校验实验设计

分析结果前先检查：
- 样本量是否充足？（做一次功效分析）
- 测试时长是否足够？（覆盖完整周循环，至少 1-2 个业务周期）
- 随机化是否干净？（检查样本比例失衡）
- 测试期间是否有外部因素影响？

发现问题就指出来——有缺陷的测试结果会误导决策。

### 第 3 步：分析结果

应用 **ab-test-analysis** 技能：

- **统计显著性**：计算 p 值与置信区间
- **效应大小**：实验组之间的绝对差与相对差
- **实际显著性**：效应是否大到对业务有意义？
- **置信区间**：真实效应的合理范围是多少？
- **细分分析**：若数据允许，检查不同用户细分的效应差异

### 第 4 步：生成分析

```
## A/B 测试分析：[测试名称]

**日期**：[今天]
**测试时长**：[X 天／周]
**总样本**：[N 位用户]

### 结果汇总
| 实验组 | 样本 | 指标 | 转化率 | 95% 置信区间 |
|---------|--------|--------|------|--------|
| 对照组 | [n] | [指标] | [X%] | [X% - Y%] |
| 实验组 | [n] | [指标] | [X%] | [X% - Y%] |

### 统计分析
- **相对提升**：[+X%]（[置信区间范围]）
- **p 值**：[X]
- **是否统计显著**：95% 置信水平下[是／否]
- **最小可检测效应**：[X%]（该测试有功效检测到的效应）

### 样本量检查
- **所需样本**：[N]／每组（在 80% 功效下检测 [X%] 的 MDE）
- **实际样本**：[N]／每组
- **结论**：[功效充足／功效不足／功效过剩]

### 决策

**建议：[发布／延长／停止]**

[结合统计显著性与实际显著性，清楚解释理由]

### 业务影响估算
若全量发布给 100% 用户：
- **预期影响**：[每月／每季度的指标变化]
- **收入影响**：[如适用]
- **置信度**：[我们对这个估算有多确定]

### 注意事项
- [关于测试有效性的任何担忧]
- [结果存在差异的细分]
- [新奇效应或其他偏差]

### 后续动作
- [基于经验下一步测什么]
- [若发布该实验组的监控方案]
```

### 第 5 步：提供后续选项

- 「需要我基于这些发现**设计一个后续实验**吗？」
- 「要不要**按细分跑一遍分析**？」
- 「需要我**生成 SQL** 来在发布后监控这个指标吗？」

## 说明

- 统计显著不等于实际显著——有足够数据时 0.1% 的提升也可能显著，但不值得发布
- 相信结果前始终检查样本比例失衡
- 新奇效应会虚高短期结果——建议发布后监控 2-4 周
- 如果测试功效不足，正确答案通常是「延长」，而不是「没有效果」
- 对收入类指标，用置信区间估算最好与最差的业务影响
- 若数据以 CSV 提供，用 Python 的 scipy.stats 生成完整分析
