## 客户旅程地图

绘制从认知到推荐的端到端客户体验，识别每个阶段的情绪、痛点与改进机会。

### 背景

你正在为 **$ARGUMENTS** 创建客户旅程地图。

如果用户提供了文件（访谈转录、问卷数据、分析数据、支持工单或已有旅程地图），先读取它们。若提供了 URL，用网络搜索了解该产品。

### 使用说明

1. **定义画像**：走完这段旅程的是谁？用带 JTBD 的具体画像，而不是泛泛的用户。

2. **梳理旅程阶段**（按产品调整）：

   | 阶段 | 说明 |
   |---|---|
   | **认知** | 他们最初如何知道这个产品？ |
   | **考虑** | 他们评估什么？对比哪些替代方案？ |
   | **获取** | 他们如何注册或购买？ |
   | **新手引导** | 首次使用产品的体验——多快获得价值 |
   | **参与** | 日常使用——养成习惯 |
   | **留存** | 什么让他们持续回来？什么可能导致流失？ |
   | **推荐** | 他们何时、为何向他人推荐这个产品？ |

3. **对每个阶段记录**：

   - **触点**：用户与产品、品牌或团队互动的地方（网站、邮件、应用内、支持、社交媒体）
   - **用户动作**：他们在这个阶段做什么
   - **想法与疑问**：他们在想什么（「这值得我花时间吗？」「我该怎么……？」）
   - **情绪**：他们的感受（兴奋、困惑、挫败、满意）——用评分或表情符号表示
   - **痛点**：摩擦、困惑、流失风险
   - **机会**：在这个节点如何改进体验

4. **识别关键时刻**：
   - **顿悟时刻**：用户第一次体验到核心价值的时刻
   - **关键时刻**：他们做出承诺或放弃的决策点
   - **流失触发点**：用户最常流失的地方

5. **创建旅程地图表**：

   | 阶段 | 触点 | 用户动作 | 情绪 | 痛点 | 机会 |
   |---|---|---|---|---|---|

6. **给出排好优先级的改进建议**：
   - 哪些痛点对转化或留存影响最大？
   - 哪些速赢能立刻改善体验？
   - 哪些需要更大投入但回报最高？

一步一步思考。保存为 markdown 文档。若需要可视化旅程地图，建议用户以这份分析为基础在 Miro 或 FigJam 中创建。
