# /analyze-feedback —— 用户反馈分析

把大量用户反馈（评论、问卷、支持工单、NPS 回复）加工成结构化洞察，包含情感分析与细分模式。

## 调用方式

```
/analyze-feedback [上传一份 NPS 回复的 CSV]
/analyze-feedback [粘贴应用商店评论或问卷回复]
/analyze-feedback [上传支持工单导出文件]
```

## 工作流程

### 第 1 步：接收反馈数据

接受任何格式：
- 带反馈文本的 CSV／Excel（可选带元数据：日期、细分、评分）
- 粘贴的文本（评论、问卷回复、Slack 消息）
- 上传的文档或反馈工具导出文件

询问：
- 这是哪类反馈？（NPS、评论、支持工单、问卷等）
- 有哪些细分需要单独分析？（用户层级、套餐、地区）
- 你想找什么？（总体主题、具体问题、随时间的趋势）

### 第 2 步：分析

应用 **sentiment-analysis** 技能：

- **情感打分**：给每条反馈分类（正向、中性、负向）
- **主题提取**：识别反复出现的主题，并把相关反馈聚类
- **频次分析**：统计每个主题出现的次数
- **细分分析**：按用户细分拆解情感与主题（若有数据）
- **趋势识别**：若有日期，识别情感随时间的位移

### 第 3 步：生成分析报告

```
## 反馈分析报告

**日期**：[今天]
**分析的反馈量**：[数量] 条
**来源**：[NPS 问卷／应用评论／支持工单／等]
**周期**：[日期范围，如可得]

### 总体情感
- 正向：[X%] | 中性：[Y%] | 负向：[Z%]
- 平均情感得分：[X/10]
- 趋势：[变好／平稳／变差]

### 主要主题
| # | 主题 | 提及次数 | 情感 | 受影响最大的细分 |
|---|-------|----------|-----------|----------------------|

### 主题深入分析

#### 主题 1：[名称] — [X] 次提及，[情感]
- **用户在说什么**：[概述，附代表性原话]
- **根因**：[是什么驱动了这条反馈]
- **影响**：[它如何影响留存、满意度或收入]
- **建议**：[该怎么处理]

[对前 5-8 个主题重复此结构]

### 细分分析
| 细分 | 反馈量 | 平均情感 | 主要主题 | 关键差异 |
|---------|--------|-------------|-----------|---------------|

### 值得注意的原话
> 「[原话]」 — [细分、情感]

### 随时间的趋势
[若有日期数据：可用于作图的情感变化数据]

### 可执行的洞察
1. [洞察 + 建议动作]
2. ...

### 信息缺口
[这些反馈没告诉你的部分——建议后续研究]
```

保存为 markdown。若输入是结构化数据（CSV），另存一份带情感打分的增强版 CSV。

### 第 4 步：提供后续选项

- 「需要我基于这些反馈模式**创建用户画像**吗？」
- 「要不要把主要主题**按功能需求分级处理**？」
- 「需要我**设计一份访谈提纲**，针对某个主题深入挖掘吗？」

## 说明

- 情感分析只是近似——要标出边界情况（讽刺、正负混杂、非英文文本）
- 主题提取应看需求背后的诉求，而不只是表层话题
- 若各细分样本量小，要说明置信度有限
- 对 NPS 数据，分别分析贬损者（0-6）、被动者（7-8）与推荐者（9-10）
- 输入是结构化数据时输出增强版 CSV，方便用户在自己的工具里使用
