# /research-users —— 用户研究综合

把原始研究数据转化为可执行的用户画像、行为细分与客户旅程地图。可接收问卷数据、访谈笔记、反馈、分析数据，或仅凭产品描述做探索性研究。

## 调用方式

```
/research-users [上传问卷结果、访谈笔记或反馈数据]
/research-users 面向代理机构的 B2B 项目管理工具——帮我理解我们的用户
/research-users [粘贴用户反馈或支持工单数据]
```

## 工作流程

### 第 1 步：接收研究输入

接受任意组合：
- 问卷回复（CSV、表格、粘贴文本）
- 访谈笔记或转录稿
- 支持工单或功能需求
- 产品分析／行为数据
- NPS 或满意度数据
- 产品描述（无数据时做探索性研究）

询问：
- 你有哪些研究？什么格式？
- 你想弄清楚什么？（用户是谁、他们有何差异、摩擦在哪里）
- 这份研究会支撑哪些决策？（路线图、定位、定价、新手引导）

### 第 2 步：构建用户画像

应用 **user-personas** 技能：

- 从数据中识别 3-4 个差异化画像
- 每个画像包含：名称、角色、目标（JTBD）、痛点、收益、行为模式
- 纳入意外洞察——数据中让你惊讶的地方
- 标注画像占比（若数据允许，说明各占用户基数的百分比）

### 第 3 步：细分用户

应用 **user-segmentation** 与 **market-segments** 技能：

- 建立行为细分（而不只是人口统计细分）
- 每个细分包含：规模、JTBD、产品契合度、付费意愿、参与度水平
- 识别最高价值细分与最高增长细分
- 把细分映射到画像（如何重叠）

### 第 4 步：绘制客户旅程

应用 **customer-journey-map** 技能：

- 绘制端到端旅程：认知 → 考虑 → 获取 → 新手引导 → 活跃使用 → 扩展 → 推荐
- 每个阶段包含：触点、情绪、痛点、顿悟时刻
- 找出最大的流失点
- 标出值得放大的愉悦时刻

### 第 5 步：生成研究报告

```
## 用户研究报告：[产品]

**日期**：[今天]
**数据来源**：[分析了什么]
**样本量**：[如适用]

### 摘要
[3-5 句话：关键发现与含义]

### 用户画像

#### 画像 1：[名称] — 「[能代表这个人的一句话]」
- **是谁**：[角色、背景、经验水平]
- **主要 JTBD**：[当我……，我想要……，这样我就能……]
- **关键痛点**：[前 3 个]
- **关键收益**：[什么让他们满意]
- **行为模式**：[他们如何使用产品]
- **占比**：[占用户基数的 X%]

[对每个画像重复此结构]

### 用户细分
| 细分 | 规模 | 主要 JTBD | 产品契合度 | 价值 | 增长 |
|---------|------|-------------|-------------|-------|--------|

### 客户旅程地图
| 阶段 | 触点 | 情绪 | 痛点 | 机会 |
|-------|------------|---------|-------------|---------------|

### 关键洞察
1. [洞察及支撑证据]
2. ...

### 建议
1. [与发现直接对应的可执行建议]
2. ...

### 未解问题
[数据没有回答的问题——建议后续研究]
```

保存为 markdown。

### 第 6 步：提供后续选项

- 「需要我**编写访谈提纲**，针对某个画像深入挖掘吗？」
- 「要不要**对这些细分做情感分析**？」
- 「需要我为最重要的画像**构建价值主张**吗？」
- 「需要我**把旅程图中的痛点按优先级排成功能机会**吗？」

## 说明

- 如果数据单薄，要坦诚说明置信度——5 次访谈只能形成假设，不能得出结论
- 画像要有用，不是装饰——每个画像都应能影响一个产品决策
- 对产品决策来说，行为细分比人口统计细分更可执行
- 旅程地图要呈现情绪，而不只是动作——用户在哪里受挫、在哪里愉悦，直接决定优先级
- 如果没有提供数据，就产出有研究支撑的假设，并建议如何验证
