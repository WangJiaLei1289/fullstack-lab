# /brainstorm —— 多视角构思

从产品经理、设计师、工程师三个视角，产出有创意的产品想法或实验设计；具体从哪里切入，取决于你是在做现有产品，还是在做新产品。

## 调用方式

```
/brainstorm ideas existing 手机银行 App 提升参与度
/brainstorm ideas new 面向忙碌父母的 AI 备餐方案
/brainstorm experiments existing 新手引导流程改版
/brainstorm experiments new 自由设计师交易平台
/brainstorm                          # 交互模式——会询问你的需求
```

## 工作流程

### 第 1 步：确定模式

解析参数，识别两个维度：

1. **要头脑风暴什么**：`ideas`（功能概念）或 `experiments`（验证性测试）
2. **产品阶段**：`existing`（持续发现）或 `new`（初期发现）

任一维度缺失，就向用户询问。两个都缺，就问：
- 「你是在为『要做什么』头脑风暴 **ideas**，还是为了验证假设而设计 **experiments**？」
- 「这是针对 **existing** 产品，还是 **new** 产品概念？」

### 第 2 步：收集上下文

向用户询问背景信息。保持对话式语气——先问最关键的问题：

**现有产品：**
- 产品是什么？当前用户是谁？
- 你在探索哪个机会领域或问题空间？
- 有哪些约束（技术债、平台限制、团队产能）？
- 之前尝试过什么？

**新产品：**
- 产品概念是什么？解决什么问题？
- 目标用户是谁？他们目前用什么替代方案？
- 现在处于哪个阶段？（餐巾纸草图、已验证的问题、早期原型）
- 最有风险的假设有哪些？

上下文可以来自上传的文件（PRD、调研文档、战略演示文稿）、粘贴的文本，或对话内容。

### 第 3 步：产出结果

**如果要头脑风暴想法**——应用 **brainstorm-ideas-existing** 或 **brainstorm-ideas-new** 技能：
- 从三个视角生成想法：产品经理（用户价值、业务影响）、设计师（UX、惊喜感、无障碍）、工程师（技术创新、平台杠杆、可扩展性）
- 每个想法给出：名称、描述、对目标用户的影响、可行性评估
- 为前 5 个想法排序并说明理由
- 标注哪些想法属于速赢，哪些属于战略押注

**如果要头脑风暴实验**——应用 **brainstorm-experiments-existing** 或 **brainstorm-experiments-new** 技能：
- 现有产品：建议 A/B 测试、原型、假门测试、绿野仙踪式（wizard-of-oz）测试、管家式（concierge）实验和技术探针（spike）
- 新产品：写出 XYZ+S 假设，并建议预原型（pretotype）实验（落地页、讲解视频、预售、管家式 MVP）
- 每个实验给出：待验证假设、方法、成功标准、投入估算、预期时间线
- 按「单位投入换来的学习量」排序

### 第 4 步：深入与迭代

给出初步结果后，主动提供：
- 「需要我把某个想法**展开**成更完整的规格说明吗？」
- 「需要我**识别**头部想法背后的**假设**吗？」（串接到 `identify-assumptions-existing` 或 `identify-assumptions-new` 技能）
- 「需要**设计实验**来验证头部想法吗？」（串接到实验模式）
- 「需要我把这些想法和当前待办列表一起**排优先级**吗？」（串接到 `prioritize-features` 技能）

## 输出格式

### 想法类输出：
```
## 头脑风暴：[产品/功能领域]
**模式**：面向 [existing/new] 产品的想法
**上下文**：[1-2 句话概述]

### 产品经理视角
1. **[想法名称]** —— [描述] | 影响：[H/M/L] | 投入：[H/M/L]
2. ...

### 设计师视角
1. **[想法名称]** —— [描述] | 影响：[H/M/L] | 投入：[H/M/L]
2. ...

### 工程师视角
1. **[想法名称]** —— [描述] | 影响：[H/M/L] | 投入：[H/M/L]
2. ...

### 前 5 个推荐
| 排名 | 想法 | 理由 | 是否速赢？ |
|------|------|-----|------------|

### 后续步骤
[如何推进这些想法]
```

### 实验类输出：
```
## 实验设计：[产品/功能领域]
**模式**：面向 [existing/new] 产品的实验

### 假设
1. **[待验证假设]** —— XYZ 格式：[X]% 的 [Y] 会在 [S 时间范围] 内 [Z]

### 推荐实验
| # | 实验 | 验证的假设 | 方法 | 投入 | 时间线 |
|---|-----------|-----------------|--------|--------|----------|

### 实验详情
[每个实验：设置、成功标准、风险、你能学到什么]
```

## 注意事项

- 现有产品：让想法扎根于当前用户行为和已验证的问题
- 新产品：先关注「用户是否想要」和「是否做得出」这两类风险
- 如果用户上传了调研文档或访谈记录，先提炼洞察，再开始头脑风暴
- 先求广度再求深度——先大量产出想法，再进入评估
