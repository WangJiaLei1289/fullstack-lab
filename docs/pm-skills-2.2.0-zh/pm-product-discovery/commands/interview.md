# /interview —— 客户访谈准备与总结

两种模式：**prep** 在你与客户交谈之前生成结构化访谈提纲，**summarize** 在访谈结束后提炼洞察。

## 调用方式

```
/interview prep 企业用户的新手引导体验
/interview summarize [粘贴访谈记录或上传文件]
/interview                    # 询问你需要哪种模式
```

## 模式

---

### Prep 模式

针对你的研究问题，生成一份结构化的访谈提纲。

#### 工作流程

**第 1 步：理解研究目标**

询问用户：
- 你想弄清楚什么？（具体的研究问题）
- 你要访谈谁？（用户细分、角色、与产品的关系）
- 你有多少时间？（15 分钟、30 分钟、60 分钟）
- 这项研究会影响哪些决策？

**第 2 步：生成访谈提纲**

应用 **interview-script** 技能：

- 遵循《The Mom Test》的原则——问对方的生活，而不是问你的想法
- 不引导、不推销，聚焦过往行为和真实场景
- 提纲按以下结构组织：

```
## 访谈提纲：[研究主题]

**研究问题**：[我们想弄清楚什么]
**目标受访者**：[谁]
**时长**：[X] 分钟

### 暖场（3-5 分钟）
[建立信任的问题，了解角色与背景]

### 核心探索（15-40 分钟）
[JTBD 追问、过往行为、当前工作方式、痛点]
- 每个问题包含：问题本身 + 为什么问 + 追问提示

### 具体话题（5-10 分钟）
[围绕特定功能或概念的针对性问题——如有需要]

### 收尾（3-5 分钟）
[开放式结尾、请对方推荐受访者、后续安排]

### 记录模板
[预先设计好的模板，方便访谈中记录洞察]

### 需要警惕的讯号
[对话跑偏的迹象，或受访者只是出于客气而非说真话]
```

**第 3 步：定制与复核**

- 按时间长短调整问题数量
- 针对用户想验证的具体假设补充追问
- 标出可能诱导受访者的问题
- 提供可打印版本（把 markdown 文件保存到工作目录）

---

### Summarize 模式

把访谈记录转化为结构化、可执行的洞察。

#### 工作流程

**第 1 步：接收访谈记录**

任何格式都可以：
- **粘贴文本**：原始记录或笔记
- **上传文件**：文档、文本文件，或会议记录的导出件
- **口头概述**：用户口述访谈内容（不是完整逐字稿）

如果输入是粗略的笔记而非完整记录，就基于现有内容处理，并说明局限。

**第 2 步：提炼与结构化**

应用 **summarize-interview** 技能：

解析记录，识别以下内容：
- **受访者画像**：角色、经验水平、用户细分、背景
- **待完成的任务（JTBD）**：受访者想达成什么
- **当前工作方式**：他们现在怎么解决这个问题
- **痛点**：挫败点、变通方案、耗时的环节
- **满意度信号**：哪些做得不错、哪些时刻让人惊喜
- **原话引用**：能承载关键洞察的原话（有的话附时间戳）
- **意外发现**：任何出乎意料或与假设相矛盾的内容
- **功能反馈**：如果聊到具体功能或概念，记录对方的反应

**第 3 步：生成访谈总结**

```
## 访谈总结

**受访者**：[匿名画像——角色、细分、经验]
**日期**：[如已知]
**时长**：[如已知]
**访谈人**：[如已知]

### 关键洞察
1. **[洞察]** —— [支撑证据/原话]
2. **[洞察]** —— [支撑证据/原话]
3. ...

### 待完成的任务（JTBD）
- **主要 JTBD**：[当我……，我想要……，这样我就能……]
- **相关 JTBD**：[其他任务]

### 当前工作方式
[受访者目前如何一步步解决这个问题]

### 痛点
| 痛点 | 严重程度 | 原话 |
|-----------|----------|-------|

### 满意度信号
| 哪些做得好 | 原因 | 原话 |
|-----------|-----|-------|

### 值得记录的原话
> 「[原话]」 —— 关于 [话题]

### 假设验证结果
| 假设 | 状态 | 证据 |
|-----------|--------|----------|

### 行动项
- [ ] [本次访谈引出的后续动作]
- [ ] [需要进一步探索的研究问题]

### 原始笔记
[如有帮助，附上带批注的关键片段]
```

把总结保存为 markdown 文件。

**第 4 步：与更广泛的研究关联**

主动提供：
- 「需要我把这份总结**和你之前做过的其他访谈总结对比**吗？」
- 「需要我根据这位受访者说的内容**更新假设**吗？」
- 「需要我从多份访谈中**提炼用户画像**吗？」

## 注意事项

- Prep 模式下，务必保留「为什么问这个问题」的批注——它能帮助访谈人不跑题
- Summarize 模式下，区分受访者*说的*和*做的*（行为证据优于口头表述）
- 标出同一场访谈内部的矛盾（说一件事，描述的却是另一件事）
- 如果记录里提到竞品，顺带收集竞争情报
- Summarize 模式下，如果提供多份记录，就做跨受访者的模式综合
