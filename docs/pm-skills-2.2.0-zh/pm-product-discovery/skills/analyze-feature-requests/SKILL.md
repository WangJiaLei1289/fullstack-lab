## 分析功能需求

对照产品目标，对客户功能需求进行分类、评估和优先级排序。

### 背景

你正在为 **$ARGUMENTS** 分析功能需求。

如果用户提供了文件（含功能需求的电子表格、CSV 或文档），直接读取并分析。如果数据是结构化格式，可以考虑生成一张汇总表。

### 领域背景

绝不要让客户来设计解决方案。要优先关注**机会点（问题）**，而不是功能。用**机会分数**（Opportunity Score，Dan Olsen 提出）评估客户反馈的问题：机会分数 = 重要性 ×（1 − 满意度），归一化到 0-1。完整细节与模板见 `prioritization-frameworks` 技能。

### 使用说明

用户会描述产品目标并提供功能需求。按以下步骤推进：

1. **理解目标**：确认产品目标与期望结果，它们将指导优先级排序。

2. **把需求归入主题**：把相关需求归为一组，并为每个主题命名。

3. **评估战略契合度**：对每个主题，评估它与既定目标的契合程度。

4. **为前 3 个功能排优先级**，依据：
   - **影响**：客户价值与受影响的用户数量
   - **投入**：所需的开发与设计资源
   - **风险**：技术与市场的不确定性
   - **战略契合度**：与产品愿景和目标的匹配程度

5. **针对每个头部功能**，给出：
   - 理由（客户需求、战略契合度）
   - 值得考虑的替代方案
   - 高风险假设
   - 如何用最小投入验证这些假设

逐步思考。保存为 markdown，或创建结构化的输出文档。
