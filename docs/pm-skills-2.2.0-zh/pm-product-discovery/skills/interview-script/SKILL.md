## 客户访谈提纲

编写一份结构化的访谈提纲，挖出真实洞察，而不只是观点。遵循《The Mom Test》原则——问对方的生活，而不是问你的想法。

### 领域背景

客户访谈是持续发现**第 1 阶段（探索）**的其中一种来源。其他来源还有：利益相关方访谈、使用分析、数据分析、问卷、市场趋势、SEO/SEM 分析。产品经理需要能直接接触用户、利益相关方、工程师和设计师——「不要通过代理人」。**产品三人组**（产品经理 + 设计师 + 工程师——Teresa Torres）应当一起做发现，而不是只有产品经理一个人。

### 背景

你正在为关于 **$ARGUMENTS** 的研究准备客户访谈提纲。

如果用户提供了文件（用户画像、假设清单、产品简报或既往访谈笔记），先读取它们。

### 使用说明

1. **厘清研究目标**：
   - 团队需要哪些具体问题得到回答？
   - 这项研究会影响哪些决策？
   - 哪些假设需要验证？

2. **编写访谈提纲**，包含以下部分：

   ### 开场（2-3 分钟）
   - 自我介绍并说明目的（是来学习，不是来推销）
   - 设定预期：「没有标准答案，我们来是想从你的经历中学习。」
   - 请求录音许可（如适用）
   - 确认可用时间

   ### 暖场：背景与处境（5 分钟）
   - 「聊聊你的角色，以及典型的一天/一周是什么样的。」
   - 「你做 [与该产品领域相关的活动] 有多久了？」
   - 目标：建立信任，了解对方的处境

   ### 核心探索：待完成的任务（15-20 分钟）

   **当前情况与行为**（用过去时，问具体事例）：
   - 「带我回顾一下你上一次 [做我们在探索的那件事] 的情况。当时发生了什么？」
   - 「你用了哪些工具或方法？」
   - 「花了多久？还有谁参与？」

   **痛点与挫败**（观察，不引导）：
   - 「这件事里最难的部分是什么？」
   - 「如果能挥一挥魔法棒，你希望改变什么？」
   - 「你尝试过怎么解决这个问题？结果如何？」

   **期望结果**（用对方的说法，不是你的）：
   - 「在这个方面，对你来说『好』是什么样子？」
   - 「你怎么判断这件事做得好不好？」

   **付费意愿 / 优先级**（押上真实筹码）：
   - 「你现在在这件事上花多少时间/多少钱？」
   - 「你找过更好的方案吗？找到了什么？」
   - 「为了解决这个问题，你愿意付出什么？」

   ### 追问技巧
   遇到有意思的线索时用这些：
   - **「再多讲讲」** —— 打开任何话题
   - **「为什么？」**（温和地问 2-3 次）—— 挖到根因
   - **「能举个具体的例子吗？」** —— 从观点转向事实
   - **「后来呢？」** —— 顺着故事往下走
   - **「那让你有什么感受？」** —— 捕捉情绪强度

   ### The Mom Test 规则
   - 问**对方的生活**，不是你的想法
   - 问**过去**，不问未来（「你会用 X 吗？」毫无价值）
   - **少说多听** —— 目标是 80/20 的比例
   - 访谈过程中**绝不推销**
   - 留意**强烈情绪** —— 它们标志着真实的痛苦或惊喜
   - **夸奖是噪音** —— 「这个听起来挺酷！」什么信息都没有

   ### 收尾（3-5 分钟）
   - 「有没有什么我没问到、但你觉得重要的？」
   - 「还有谁我应该去聊聊？」
   - 感谢对方的时间
   - 说明后续安排（如有）

3. **定制提纲**：根据具体产品领域、用户画像和研究目标调整问题。按可用的访谈时长增删章节。

4. **附上记录模板**：
   ```
   受访者：[姓名 / ID]
   日期：[日期]
   关键任务：[对方想达成什么]
   当前方案：[现在用什么]
   最大痛点：[对方最难受的一点]
   期望结果：[成功是什么样子]
   付费意愿：[投入了多少 / 愿意投入多少]
   意外发现：[出乎意料的事]
   后续动作：[下一步]
   ```

保存为 markdown，把提纲和记录模板都包含进去。
