# /north-star —— 北极星指标定义

找出最能代表产品所交付价值的单一指标，以及驱动它的输入指标。为你的业务类型分类，并对照经过验证的标准做校验。

## 调用方式

```
/north-star B2B SaaS for team collaboration
/north-star Consumer fitness app monetized through subscriptions
/north-star Help me fix our North Star — we're tracking DAU but it doesn't feel right
```

## 工作流程

### 第 1 步：理解产品

需要了解：
- 产品是什么？它为用户交付什么价值？
- 商业模式是什么？（订阅、交易、广告、平台/市场）
- 目前跟踪了哪些指标（如果有）
- 为什么现在要做这件事？（新产品、现有指标感觉不对、团队对齐）

### 第 2 步：判断业务类型

应用 **north-star-metric** 技能：

判断产品正在玩哪一类游戏：
- **注意力（Attention）**：收入来自用户时间/参与度（媒体、社交、广告支持）
- **交易（Transaction）**：收入来自购买（电商、平台/市场）
- **生产力（Productivity）**：收入来自效率提升（SaaS、工具、B2B）

游戏类型决定了什么样的北极星指标才合理。

### 第 3 步：定义北极星指标

- 提出 2-3 个北极星指标候选
- 对照 7 条标准逐一校验：
  1. 体现交付给客户的价值
  2. 是收入的先行指标
  3. 可度量、可跟踪
  4. 整个团队都能理解
  5. 可行动（团队能影响它）
  6. 不是虚荣指标
  7. 不能在未交付真实价值的情况下被刷高
- 推荐最有说服力的候选，并给出理由

### 第 4 步：定义输入指标

针对选定的北极星指标，找出 3-5 个输入指标：
- 每个输入指标都应是直接驱动北极星指标的杠杆
- 每个指标都应有明确的团队负责
- 所有输入指标合在一起，应当 MECE 地解释北极星指标的变动

### 第 5 步：生成指标框架

```
## 北极星框架：[产品]

**业务类型**：[注意力 / 交易 / 生产力]

### 北极星指标
**指标**：[准确名称]
**定义**：[计算公式或度量方法]
**为什么是它**：[能解释价值、领先收入、可行动]
**当前值**：[如已知]
**目标**：[目标值]

### 校验
| 标准 | 是否通过？ | 说明 |
|----------|-------|-------|
| 体现价值 | [是/否] | [说明] |
| 先行指标 | [是/否] | [说明] |
| 可度量 | [是/否] | [说明] |
| 可理解 | [是/否] | [说明] |
| 可行动 | [是/否] | [说明] |
| 非虚荣指标 | [是/否] | [说明] |
| 不可被刷高 | [是/否] | [说明] |

### 输入指标
| 输入指标 | 如何驱动北极星指标 | 负责人 | 当前值 | 目标值 |
|-------------|---------------------|-------|---------|--------|

### 指标星座
[展示北极星指标 → 输入指标 → 团队动作的树状图]

### 反向指标
| 指标 | 防范的风险 |
|--------|-----------------|

### 已规避的反模式
[为什么我们没有选择 DAU、收入或其他常见但有缺陷的指标]
```

保存为 markdown。

### 第 6 步：提供后续选项

- 「要不要我**围绕这套指标搭建完整的指标看板**？」
- 「要不要我**基于这些指标创建 OKR**？」
- 「要不要我**编写 SQL 查询**来计算这些指标？」

## 注意事项

- 北极星指标应衡量*交付的价值*，而不只是*活动*——「日活跃用户」只有在活跃使用等于价值交付时才是好指标
- 收入从来不是好的北极星指标——它是滞后指标，无法体现用户价值
- 输入指标才让框架具备可行动性——没有它们，北极星指标只是一个虚荣看板
- 每年或在商业模式发生重大变化时重新审视北极星指标
- 反向指标可以防止古德哈特定律——当一个指标变成目标，它就不再是好的指标
