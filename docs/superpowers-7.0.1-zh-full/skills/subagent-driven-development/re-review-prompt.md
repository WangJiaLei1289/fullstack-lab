# 定范围复审提示词模板

在一轮修复之后分派复审时使用本模板。复审者核实各条发现项是否已得到处理，并检查修复 diff 是否带来新的破坏。它不是一次全新的评审——完整评审已经做过了。

**目的：** 核实上一次评审中的每条发现项都已得到处理，并且修复本身没有弄坏任何东西。

```
子代理（general-purpose）：
  description: "复审任务 N 的第 R 轮修复"
  model: [MODEL —— REQUIRED：按 SKILL.md 的「模型选择」选一个；省略
         model 的话，会静默继承会话里最贵的那个模型]
  prompt: |
    你正在复审某个任务的一轮修复。上一次评审产出了
    一批发现项；某个实现者已经尝试修复它们。你的任务是：
    对每条发现项给出判定，并检查修复 diff —— 别的什么都不做。

    ## 任务

    阅读任务简报：[BRIEF_FILE]

    ## 待核实的发现项

    [FINDINGS]

    ## 修复

    阅读实现者的报告（修复报告会追加在末尾）：
    [REPORT_FILE]

    **修复基线：** [FIX_BASE_SHA]（上一次评审看到的 head）
    **当前提交：** [HEAD_SHA]
    **diff 文件：** [DIFF_FILE]

    diff 文件读一遍就够了——里面包含修复提交、变更统计摘要，
    以及带上下文的修复 diff。不要重新运行 git 命令。
    如果 diff 文件缺失，就自己获取 diff：
    `git diff --stat [FIX_BASE_SHA]..[HEAD_SHA]`，以及
    `git diff [FIX_BASE_SHA]..[HEAD_SHA]`。

    你对这个检出的评审是只读的。不要改动工作
    树、索引、HEAD 或分支状态，任何形式的改动都不行。

    ## 你不分派子代理

    这次评审全部自己做。绝不派子代理去评审 diff 的
    任何一部分，也绝不为第二意见再派一个评审者。
    这套流程已经为这项工作提供了它应得的全部评审席位；你
    派出的评审者只会以全额成本重复其中一个席位，而它的
    判定毫无分量。如果你觉得这个 diff 一次跑不完，
    就自己分多遍评审，并在报告里说明。

    ## 范围

    你的范围是发现项清单和修复 diff。为每一条发现项给出判定。
    检查修复 diff 里有没有修复本身引入的新问题。
    不要（Do NOT）复审修复没有碰过的代码：如果你注意到一个完全
    在修复 diff 之外的问题，就放到「范围外观察」下报告——它
    不会阻塞这个任务，也不会延长循环。范围更广的
    整分支评审会在所有任务完成后进行。

    ## 测试

    实现者重新运行了覆盖被改动代码的测试，并把结果追加
    到报告文件里。把这份报告当作未经核实的声明：
    确认修复报告点名了覆盖这些改动的测试、并展示了它们的输出，
    再对照 diff 核实这些声明。不要为了让他们的报告
    得到确认而重跑整个测试套件。只有当阅读代码冒出一个
    现有运行结果回答不了的具体疑点时，才运行测试——而且只跑聚焦的测试，
    绝不跑整包级别的测试套件。

    ## 输出格式

    你的最终消息就是报告本身：直接从第一条
    发现项的判定开始。每一行要么是判定，要么是带 file:line 的发现项，
    要么是你执行过的检查——不要开场白，不要过程叙述。

    ### 发现项判定

    按顺序处理「待核实的发现项」里的每一条发现项：
    - **[finding one-liner]** —— ADDRESSED | NOT ADDRESSED，并附 file:line
      证据。「尝试过」不算已处理：那个具体缺陷必须
      不再存在。

    ### 修复 diff 中的新破坏

    修复本身弄坏或引入的任何东西，标明严重程度
    （Critical/Important/Minor）并附 file:line。没有问题就写「无」。

    ### 范围外观察

    你注意到、但完全在修复 diff 之外的问题。不阻塞；控制器会
    把这些记入台账，供最终评审使用。没有就写「无」。

    ### 判定

    **修复轮次：** [所有发现项都已处理，没有新的 Critical/Important
    破坏 | 仍有发现项未处理] —— 列出未处理项。
```

**占位符：**
- `[MODEL]` —— 必需：按 SKILL.md 的模型选择确定的评审者模型；对小修复 diff 的定范围复审取便宜到中档的层级
- `[BRIEF_FILE]` —— 任务简报文件（实现者所依据的同一个文件）
- `[FINDINGS]` —— 上一次评审中的 Critical/Important 发现项与规格缺口，逐字抄来，每条一个要点
- `[REPORT_FILE]` —— 实现者的报告文件（修复报告追加在其后）
- `[FIX_BASE_SHA]` —— 上一次评审看到的 head
- `[HEAD_SHA]` —— 当前提交
- `[DIFF_FILE]` —— `bash scripts/review-package PLAN_FILE FIX_BASE HEAD` 打印出的路径

**复审者返回：** 逐条发现项的判定（ADDRESSED / NOT ADDRESSED）、修复 diff 中的新破坏、范围外观察，以及本轮结论。
