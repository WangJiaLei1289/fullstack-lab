把文件头部的版本字段标注为历史证据、未经验证的快照、当前观测或未知。`environment.json` 对每个环境字段及其支撑位置都带有相同的来源区分。

## 这是什么

这是一份经过清洗的编码代理会话记录，该会话安装了 superpowers 并且出了问题。它让不在场的人或代理能够判断 superpowers 是否起了作用，如果起了作用又该改什么。其中的报告用 `path:line` 证据说明发生了什么。按设计，它不包含对 superpowers 的诊断，也不提出修复方案；那是读者的事。

## 文件

- `report.md` —— 诊断报告（问题陈述、结论、环境、会话、时间线、发现、是否相关、覆盖说明）。
- `case.md` —— 分析师据以工作的案例文件。
- `environment.json` —— 环境一节的机器可读副本。
- `timeline.md` —— 按轮次的时间线。
- `findings/<dimension>.md` —— 每个维度的分析师原始发现。
- `transcripts/<session-id>.md` —— 每个被检查会话按轮次浓缩后的呈现（绝不是原始 JSONL）。按级别列出工具结果正文：

  | 级别 | 工具结果正文 |
  |---|---|
  | skeleton | 有意限制；替换为 `[tool result: <tool>, <bytes> bytes, exit <code>]` |
  | evidence | 保留被引用事件，包括支撑发现所需的命令和结果 |
  | full | 全部保留 |
- `scrub-log.md` —— 用到的每个占位符及其类别（绝不包含原始值）。

## 怎么读

先看 `report.md` 第 1–2 节，再看第 7 节（是否相关）及其引用的证据行，然后看 `transcripts/` 中对应的轮次。`path:line` 引用指向报告者机器上的原始文件；相同的行号在浓缩后的对话记录里以 `[L<n>]` 标记保留。

## 脱敏

占位符形如 `<EMAIL-1>`、`<PERSON-2>`、`<SECRET-3>`、`<HOST-4>`、`<REPO-5>`、`<ORG-6>`、`<PROPRIETARY-7>`；家目录路径会被改写成 `~/…`。在同一个交付包内，相同占位符始终指代相同的原始值。

## 制作者须知

完成的交付包会用实际结果替换这些说明。

清洗之后，只用这个交付包检查每一条实质性的导出发现：把它的引用解析到包内包含的对话记录/来源标记，读取被引用的命令/结果或引文，并确认它支撑该论断。仅有路径和行号存在是不够的。当脱敏级别或必要的保留导致支撑缺失时，记录具体的局限。

核对报告、案例、环境、发现、README 以及任何本地 issue 草稿。针对最终文件刷新 scrub 日志的计数（不把日志本身算在内）。移除过时的导出说明；把交付包制作与归档交付区分开。保留从历史锚点到包内证据的映射。

把独立的隐私审计与证据可用性分开记录：
- 隐私审计：CLEAN，或有未解决的遗漏。
- 证据支撑：有支撑或受限，并附受影响的发现及原因。

如果检查后内容发生变化，就重做受影响的检查。为现有的归档批准展示最终日志、文件清单和两项结果。归档已评审的文件，并确认交付的归档与之一致。在已评审的交付包之外记录归档交付，而不是在批准之后改动其内容。清洗并不等于完整的隐私认证。
