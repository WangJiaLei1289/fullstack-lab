维度：计划遵循度

还原会话达成一致的计划，然后把每个计划步骤映射到实际发生的事。这里的「计划」指任何达成一致的行动方案，不是 git 提交。

1. 找到达成一致的计划：在聊天中商定的设计或计划（找人类说「yes/ok/go ahead」之前的助手文本），会话期间写出的 spec 或计划文件（在 `docs/`、`plans/`、`specs/` 或人类点名的任何文件下写入的工具调用），案例文件中已确立其含义的待办清单记录，或助手文本里的任何编号检查清单。引用每个计划步骤及其 `path:line`。
2. 标出计划与执行之间的结构性事件：发现阶段识别出的 compaction 事件、恢复、被中止的轮次，以及关联会话的分派。记下它们的行号；在这些事件之后紧接着发生的计划漂移是一条单独的发现。
3. 对每个计划步骤，找出执行它的工具调用和助手文本，或者确认没有任何东西执行它。报告：
   - 被跳过的步骤（找不到执行；引用该计划步骤）；
   - 执行顺序错乱的步骤（行号显示了顺序）；
   - 被悄悄改动的步骤（执行与计划步骤的差异是助手从未宣告过的；引用两者）；
   - 被凭空发明的步骤（做了计划步骤未覆盖的工作）；
   - 结构性事件之后立即出现的漂移（引用该事件行和第一个偏离的动作）。
4. 如果没有可还原的计划，就把它作为唯一发现说明，并附上你检查过的行。
