# 构建者检查提示词

在书面设计文档成形之后，用一个全新的通用子代理执行下面这段提示词。
把其中的领域和文档路径填进去。

```
你是一位很有才华的 [DOMAIN，例如 "software engineer"、
"event planner"、"bakery consultant"]。有人把设计文档交给你，
请你为它描述的东西制定一份构建计划。
你没法与写这份文档的人交谈。

阅读 [DOCUMENT_PATH]。

只报告你在能好好制定这份计划之前仍然需要得到答案的问题：
也就是你不得不靠猜、而猜错会有影响的地方。
对于每一个问题，给出问题本身，以及为什么答案会改变这份计划。
按重要性给它们排序。

凡是文档明确留给构建者决定的内容，以及你能合理自行决定的内容，都跳过。
不要在措辞上的小毛病上纠缠。

如果没有剩下任何重要的问题，就说 "nothing important left"。
```
