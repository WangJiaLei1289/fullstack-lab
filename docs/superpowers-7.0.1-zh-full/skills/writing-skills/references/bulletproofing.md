# 让技能抵御自我合理化

属于 superpowers:writing-skills 的一部分。当基线失败属于纪律性失败时使用：
代理明明知道规则，却在压力下跳过它。

## 让技能抵御自我合理化

强制纪律的技能（如 TDD）必须能抵御自我合理化。代理很聪明，在压力下一定会去找漏洞。

**范围：** 这套工具针对的是纪律性失败——代理知道规则，却在压力下跳过它。对于产出形态不对或漏掉要素的情况，基于禁止的做法反而会适得其反；请改用「让表达形式匹配失败类型」一节里给出的那些形式。

**心理学备注：** 理解说服技巧为什么有效，能帮你系统地运用它们。研究基础见本目录下的 persuasion-principles.md（Cialdini, 2021; Meincke et al., 2025），涉及权威、承诺、稀缺、社会认同与统一性原则。

### 把每个漏洞都明确堵死

不要只陈述规则——要禁止具体的变通做法：

<Bad>
```markdown
写测试之前写代码？删掉。
```
</Bad>

<Good>
```markdown
写测试之前写代码？删掉。重新开始。

**没有例外：**
- 不要把它留作「参考」
- 不要一边写测试一边「改造」它
- 不要看它
- 删掉就是删掉
```
</Good>

### 回应「精神 vs 字面」的争论

把根本性原则早早放进去：

```markdown
**违背规则的字面要求，就是违背规则的精神。**
```

这能一次性切断「我是在遵循精神」这一整类自我合理化。

### 建立自我合理化对照表

从基线测试中收集自我合理化（见下文「测试」一节）。代理提出的每一个借口都要进表：

```markdown
| 借口 | 现实 |
|--------|---------|
| 「太简单，不用测」 | 简单代码也会坏。测试只要 30 秒。 |
| 「我之后会测」 | 测试立刻通过，什么也证明不了。 |
| 「事后测试能达到同样目的」 | 事后测试 = 「这段代码做了什么？」；测试先行 = 「这段代码应该做什么？」 |
```

### 建立危险信号清单

让代理在自我合理化时容易自查：

```markdown
## 危险信号 —— STOP，然后重新开始

- 测试之前先写代码
- 「我已经手动测过了」
- 「事后测试能达到同样的目的」
- 「重要的是精神，不是仪式」
- 「这次情况不一样，因为……」

**以上任何一条都意味着：删掉代码。用 TDD 重新开始。**
```
